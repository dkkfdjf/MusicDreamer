# 设计：单击播放条头像开关歌词面板

日期：2026-09-01
项目：MusicDreamer-frontend
状态：已确认

## 背景

歌词面板（`LyricsPanel.vue`，内容区右缘常驻列）目前唯一的开关入口是播放条中间的「詞」按钮
（`PlayerBar.vue` → `lyrics.togglePanel()`）。需求：单击播放条左下角"正在播放歌曲"的封面头像
也应开关歌词面板。注意：不是单击首页歌曲列表/轮播里的歌曲——是播放条上那个头像。

## 交互规范

| 状态 | 单击封面行为 |
|---|---|
| 未播放任何歌曲（`player.current` 为空，头像显示 ♪ 占位） | 忽略，无任何反应 |
| 有歌，歌词面板关闭 | 打开右侧歌词面板（等同点「詞」） |
| 有歌，歌词面板已开 | 关闭面板（toggle 对称语义） |

## 实现要点（仅改 `src/components/PlayerBar.vue`）

1. 模板：`.track .cv` 容器加 `@click="onCoverClick"`；title 动态——
   无歌不提示；有歌未开 →「单击显示歌词」；已开 →「单击收起歌词」。
2. 脚本：
   ```js
   function onCoverClick() {
     if (player.current) lyrics.togglePanel()
   }
   ```
3. 样式：`.track .cv` 仅在有歌时 `cursor: pointer`（`:class` 控制）；悬停轻微缩放
   `transform: scale(1.03)`，与项目现有悬停反馈风格一致。

## 数据流

`dblclick → lyrics.togglePanel() → panelOpen 翻转 → LyricsPanel 宽度动画 +
App.vue 的 lyrics-on class → 首页 hero 自动降级单列`。
全部复用现有链路：无新增状态、无新增事件、无跨组件通信。
「詞」按钮与单击头像两个入口驱动同一 `panelOpen`，状态天然同步。

## 边界情况

- 单击瞬间歌曲切换/清空：函数入口判空，安全。
- 头像图加载失败显示 ♪ 占位（`coverFail`）：单击照常生效——歌词属于歌曲而非封面图。
- 触屏：「詞」按钮仍是主入口，单击是桌面端加分手势。
- 项目先例：`DesktopLyrics.vue` 已用 `@click` 关闭歌词条，风格一致。

## 测试方式（手动）

1. 播放一首歌 → 单击头像 → 面板展开，「詞」按钮变开启态（品牌渐变）。
2. 再单击 → 面板收起，「詞」按钮回未开启态。
3. 未播放时单击 → 无反应，无 cursor 提示。
4. 面板开着时点「詞」或面板 × → 也能关闭（两入口状态同步）。

## 否决的备选方案

- 单击+单击双语义（250ms 延时区分）：让所有关闭路径都迟钝 250ms，手感差。
- 整个左下角曲目区可单击：热区过大易误触，且歌名区未来可能需要单击语义。
- 首页 SongGrid 卡片"点击暂停→弹歌词"三态循环（此前会话误解需求实现、未提交，
  已按用户决定 `git checkout` 撤销）：歌词入口只保留播放条头像单击 + 「詞」按钮。

## 明确不做

- 不改首页歌曲卡片/hero 轮播的任何点击行为。
- 不接 `DesktopLyrics.vue` 悬浮歌词条（保持孤立，另行处理）。
