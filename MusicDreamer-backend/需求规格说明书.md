- **前端框架**：Vue 3.x + Element Plus + WebSocket（实时推送）

## 2. 项目概述

### 2.1 项目背景

随着互联网技术的快速发展和数字音乐的普及，在线音乐平台已成为人们获取音乐内容的主要渠道。然而，现有主流音乐平台对音乐创作者的门槛较高，普通音乐爱好者难以便捷地分享原创作品。

### 2.2 项目目标

"Music Dreamer悦享音乐"致力于打造一个开放、便捷的音乐分享平台，实现以下目标：

1. **降低音乐发布门槛**：简化音乐发布流程，让普通音乐创作者能够轻松分享作品
2. **提升用户体验**：提供流畅的音乐播放、智能推荐和个性化服务
3. **构建完整生态**：涵盖内容创作、发布、传播、消费全链路
4. **支持高效管理**：提供完善的后台管理功能，保障平台健康运营

### 2.3 项目特色

- **微服务架构**：采用Spring Cloud Alibaba微服务技术，系统可扩展性强
- **前后端分离**：使用Vue.js + Spring Boot，提升开发效率和用户体验
- **智能推荐**：基于用户行为数据的个性化内容推荐
- **全流程管理**：运用华为云DevCloud实现项目管理、代码托管、编译构建、测试部署一体化
- **开源技术栈**：采用主流开源技术，降低技术成本和维护难度

### 2.4 目标用户与角色体系

系统采用**统一用户体系 + 角色权限**模式，一个用户账号可以拥有多种角色：

| 用户类型 | 角色编码 | 描述 | 获取方式 |
|---------|---------|------|---------|
| 普通用户（听众） | ROLE_USER | 音乐消费者，可以收听、收藏、创建歌单 | 注册默认获得 |
| 认证歌手 | ROLE_SINGER | 音乐创作者，可以上传、发布、管理原创音乐 | 申请认证后获得 |
| 管理员 | ROLE_ADMIN | 平台运营者，拥有系统管理权限 | 系统初始化分配 |

**角色升级机制**：普通用户可以申请成为认证歌手，经管理员审核后获得歌手角色权限。

## 3. 系统架构

### 3.1 总体架构

系统采用**微服务架构**，基于**Spring Cloud Alibaba**技术栈构建，分为以下层次：

```
                        ┌──────────────────────────────────────────┐
                        │  Gateway :80 (路由/鉴权，新增 /media/**)  │
                        └───────┬───────────────────┬──────┘
                                │ Nacos 服务发现     │
   ┌──────────┬──────────┬──────┴─────┬─────────┬───────────┴─┬─────────┐
   │Mod_login │Mod_music │ Mod_media  │Mod_upld │Mod_songList │Mod_like │
   │  :8001   │  :8002   │  :8010 ★   │  :8007  │  :8008      │  :8009  │
   └──────────┴──────────┴─────┬──────┴─────────┴─────────────┴─────────┘
                             │ 子进程(spawn数组参数)
                   ┌─────────┴─────────┐
                   │ yt-dlp/ffmpeg/    │  开发期=宿主机现有工具(PATH探测)
                   │ whisper.cpp       │  容器期=镜像内Linux版
                   └─────────┬─────────┘
                             │ 文件落盘 /data + Feign 写库
   基础设施(Compose): MySQL:3306  Redis:6379  Nacos:8848
   监控(Compose):    Prometheus:9090  Grafana:3000  Alertmanager:9093
```

**架构说明**：
- **Mod_media (8010)**：媒体处理服务，负责下载/转码/响度分析/转写等CPU密集型任务
- **Mod_music (8002)**：音乐服务，负责播放上报、历史记录、榜单统计
- **Mod_login (8001)**：用户登录服务，负责认证授权
- **Gateway**：API网关，统一入口，路由分发和鉴权
- **Nacos**：服务注册发现和配置中心
- **监控体系**：Prometheus采集指标，Grafana可视化，Alertmanager告警

### 3.2 核心实体关系

系统包含三类核心角色实体：

- **歌手（Singer）**：音乐内容创作者，负责上传、发布、管理歌曲
- **管理员（Admin）**：系统运营者，负责管理用户、歌曲、公告
- **听众（Listener）**：音乐消费者，负责收听、收藏、管理歌单

### 3.3 核心数据模块

- **歌曲库**：存储所有已发布的歌曲及元数据
- **公告中心**：存储系统公告和通知信息

### 3.4 微服务模块划分

| 模块 | 端口 | 服务名 | 状态 | 职责 |
|---|---|---|---|---|
| Mod_login | 8001 | loginService8001 | 现有 | 用户登录、注册、认证授权 |
| Mod_music | 8002 | musicService8002 | 增强 | 播放上报、历史/最近/榜单、响度字段下发 |
| Mod_upload | 8007 | uploadService8007 | 现有 | 文件上传处理 |
| Mod_songList | 8008 | songListService8008 | 现有 | 歌单管理 |
| Mod_like | 8009 | likeService8009 | 现有 | 收藏点赞功能 |
| Mod_media | 8010 | mediaService8010 | **新增** | 下载/转码/响度/转写/字幕/工具与模型管理 |
| Mod_setting | 8005 | settingService8005 | 增强 | 系统键值配置中心 |
| Gateway | 80 | musicGateway | 新增 | API网关、路由分发、统一鉴权 |

**Mod_media 独立成服务的原因**：
- 子进程CPU密集（转码/转写分钟级）
- 生命周期与HTTP请求不同步（必须任务化）
- 镜像大（工具链）
- 与在线服务隔离、独立伸缩

### 3.5 服务间通信

- **同步调用**：Feign + Ribbon（服务间HTTP调用）
- **异步长任务**：media_task 落库 + Worker 消费（进程可死、任务状态不丢，见10.8任务自愈）；@Async + CompletableFuture 仅用于短异步（如通知发送）
- **熔断降级**：Sentinel（服务保护）
- **配置管理**：Nacos Config（动态配置）

### 3.6 数据存储架构

**分层存储架构**：

```
基础设施层:
├── MySQL:3306           (关系型数据库，主业务数据)
├── Redis:6379           (缓存、会话、验证码)
├── Nacos:8848           (服务注册、配置中心)
└── 存储层(分阶段策略):
    ├── 开发期存储:
    │   ├── /data/music/    (音频文件)
    │   ├── /data/image/    (封面图片)
    │   ├── /data/lyric/    (歌词文件)
    │   ├── /data/task/     (临时文件)
    │   ├── /opt/tools/     (处理工具)
    │   └── /models/        (AI模型)
    └── 生产期存储:
        ├── OSS/CDN         (音频文件，CDN加速分发)
        ├── 图片CDN         (封面图片，智能压缩)
        └── 冷存储归档       (历史数据备份)
```

**存储策略说明**：
- **开发期**：使用本地Docker卷挂载，快速开发和测试
- **生产期**：使用OSS+CDN，支持高并发访问和全球分发
- **冷热分离**：热数据CDN加速，冷数据归档存储
- **渐进式演进**：开发环境可无缝切换到生产存储架构

## 7. 业务流程

### 7.1 用户注册流程

```
开始 → 输入注册信息 → 验证信息格式 → 发送激活邮件 → 
用户激活 → 注册成功（默认role=0普通用户） → 结束
```

### 7.2 歌手认证流程

```
普通用户登录 → 申请歌手认证 → 填写艺人信息 → 
上传身份证明 → 提交审核（singer_status=1） → 
管理员审核 → 审核通过（role=1，singer_status=2） → 
获得歌手权限 → 结束
```

### 7.3 歌曲发布流程（审核制）

```
歌手登录 → 上传歌曲文件 → 填写歌曲信息 → 
提交审核（status=1审核中） → 管理员审核内容 → 
审核通过（status=2已发布） → 发布到歌曲库 → 
系统推荐 → 结束

备注：如审核驳回（保持status=1，记录reject_reason）， 
歌手修改后可重新提交审核
```

### 7.4 音乐推荐流程

```
用户播放歌曲 → 记录播放历史（play_history表） → 
分析用户偏好 → 匹配相似歌曲 → 生成推荐列表 → 
展示给用户 → 结束
```

### 7.5 歌曲违规处理流程

```
管理员发现违规歌曲 → 歌曲下架（status=0） → 
记录违规原因 → 降低歌手信誉分 → 
严重违规则禁用歌手账户（status=0） → 
通知歌手 → 结束

### 8.2 数据关系

- 一个用户可以创建多个歌单

### 10.3 媒体处理服务详细设计

#### 进程执行器（基础设施）

Mod_media的核心是进程执行器，一切工具调用的唯一出口，遵循六条强约束：

1. **数组参数**，绝不拼shell字符串（防注入）
2. **全异步**（ProcessBuilder + CompletableFuture）
3. **stderr必须收集**（ffmpeg ebur128结果在stderr）
4. **stdout按行回调**（进度解析）
5. **超时控制**（定时器kill进程）
6. **输出编码统一UTF-8**

#### 媒体任务类型

| 任务类型 | 说明 | 超时 |
|---------|------|------|
| DOWNLOAD | 音视频下载 | 20min |
| TRANSCRIBE | AI语音转文字 | 30min |
| LOUDNESS | 响度分析 | 10min |
| SUBTITLE | 字幕下载转换 | 5min |
| MODEL_DOWNLOAD | AI模型下载 | 60min |
| TOOL_UPDATE | 工具自动更新 | 10min |

#### 下载管线流程

```
提交下载 → URL识别 → 查重检查 → 创建任务
  ↓
元数据获取(yt-dlp) → 下载音频 → 转码MP3 → 入库
  ↓
响度分析 → 字幕处理 → AI转写 → 完成
```

### 10.7 熔断降级设计

#### 组件选型：Sentinel

采用Sentinel作为熔断降级组件，与Nacos同属Spring Cloud Alibaba生态。

#### 核心配置

```yaml
spring.cloud.sentinel:
  transport:
    dashboard: "sentinel:8858"
    port: "8719"
feign.sentinel.enabled: true  # Feign调用自动纳入熔断
```

#### 熔断点分析

| 调用链 | 风险 | 保护方式 |
|-------|------|---------|
| Mod_media →Feign→ Mod_music | 对方宕机导致任务卡死 | Sentinel熔断 + fallback |
| Gateway → 各业务服务 | 单服务故障拖垮入口 | 网关超时 + 熔断 |
| Mod_media → 外部站点 | 412风控/网络抖动 | 站点级断路器 |
| POST /media/download | 恶意刷接口 | Sentinel限流 |

#### 降级策略

| 类型 | 策略 |
|------|------|
| 查询类 | Redis缓存兜底 → 无缓存返回"数据暂时不可用" |
| 写入类 | 任务状态回PENDING，@Scheduled每30s重试3次 |
| 消息通知 | 仅记日志，通知永远不阻塞主流程 |
| 外部站点 | 连续5次失败 → 断路器OPEN → 10min后半开 |

#### Sentinel规则（控制台动态配置）

| 资源 | 规则类型 | 配置值 |
|------|---------|--------|
| /media/download | QPS限流 | 2/s（单用户1/s） |
| Feign:musicService8002 | 异常比例 | >50%（10s窗口）→ 熔断30s |
| Feign:msgService8006 | 慢调用比例 | RT>1s占60% → 熔断60s |
| /music/** | QPS限流 | 200/s总闸 |

### 10.8 高可用设计

#### 单点故障分析

| 组件 | 单点风险 | 故障影响 | 课设对策 | 生产演进 |
|------|---------|---------|---------|---------|
| MySQL | ★★★ 唯一状态库 | 全部业务不可用 | 卷持久化 + 每日备份 | 主从复制 + MHA |
| Redis | ★★ 缓存/验证码 | 验证码失效 | 降级直查DB | 哨兵/集群 |
| Nacos | ★★ 注册中心 | 已运行服务不受影响 | derby数据目录挂卷 | 3节点集群 |
| Gateway | ★★★ 唯一入口 | 全部流量中断 | restart:always | LB + 多实例 |
| Mod_media | ★★ 任务执行器 | 下载/转写中断 | 任务自愈机制 | 多实例 |
| 存储卷/data | ★★ 文件唯一副本 | 音乐/封面丢失 | 定期备份 | NAS/对象存储 |

#### 任务自愈机制

服务启动时的自愈流程：
```
① 遗留RUNNING状态 → 更新为FAILED（服务重启导致中断）
② 遗留PENDING状态 → 保留，Worker启动后自然消费
③ 清理孤儿临时文件 → 扫描删除 *_temp* 文件
④ 工具自检通过后 → Worker才开始接任务
```

### 10.9 监控告警体系

#### 监控数据流

```
各服务(Actuator+Micrometer)
  → /actuator/prometheus
  → Prometheus:9090 (指标采集)
  → Grafana:3000 (可视化)
  → Alertmanager:9093 (告警)
  → SMTP (邮件通知)
```

#### 业务指标

| 指标 | 类型 | 用途 |
|------|------|------|
| media_task_total{type,status} | Counter | 任务量/成功率 |
| media_task_duration_seconds{type} | Timer | 转码/转写耗时分布 |
| media_task_queue_size | Gauge | 积压告警 |
| media_tool_alive{tool} | Gauge | 工具健康状态 |

#### 告警规则与业务对应关系

| 告警规则 | 触发条件 | 用户感知 | 处理措施 | 对应功能 |
|---------|---------|---------|---------|---------|
| TaskQueueBacklog | 队列积压 > 10个持续2分钟 | 任务进度变慢，提示"系统繁忙" | 扩容Mod_media实例 | F041/F042上传功能 |
| ToolUnhealthy | yt-dlp不可用持续5分钟 | 下载功能不可用，提示"暂时无法处理" | 管理员触发工具自动更新 | 下载/转码功能 |
| ServiceDown | Mod_music不可用持续30秒 | 播放功能不可用，返回缓存数据 | 自动熔断，降级到Redis | F031播放功能 |
| HighJvmGc | 老年代GC频率 > 1次/秒 | 页面响应变慢 | 重启服务，扩容内存 | 全局性能 |
| TaskFailureSpike | 任务失败率 > 20%持续5分钟 | 上传/处理功能频繁失败 | 检查外部站点状态 | F041/F042功能 |

#### 告警响应流程

```
告警触发 → 判断严重级别
    ↓
【严重告警】→ 立即通知管理员 → 自动/手动处理 → 恢复确认
【一般告警】→ 记录日志 → 定期检查 → 预防性处理
    ↓
告警解除 → 更新状态 → 生成告警报告
```
