# MusicDreamer 团队部署教程（从零到跑通）

> 面向新队友：一台空白 Windows 机器 → 本地跑通整个系统。
> 前后端是两个仓库，本文从拉代码开始一步步走。
> 卡住先看文末「常见问题速查表」，90% 的坑都在那。

## 0. 路线总览

| | 路线 A：Docker（推荐） | 路线 B：全部本机安装 |
|---|---|---|
| MySQL / Redis / Nacos | `docker compose up -d mysql redis nacos` 一条命令 | 自己装 MySQL 8 + Redis，Nacos 用脚本拉 |
| 适合 | 装了 Docker Desktop 的机器 | 不想用 Docker 的机器 |
| 后端 / 前端 | 一样：IDEA（或 Maven）+ npm | 同左 |

## 1. 自装清单（仓库里没有的，先装好）

| 软件 | 版本要求 | 用途 / 备注 |
|---|---|---|
| Git | 任意新版 | 拉代码；下面的命令都在 **Git Bash** 里跑 |
| JDK | 17 ~ 22（**别用 25 EA**，Lombok 编译会挂） | 后端编译 + 本机 Nacos 启动 |
| Node.js | 18+ | 前端 + `fetch-tools.js` 拉工具 |
| Docker Desktop | 任意近期版 | 仅路线 A；装完确认它能正常启动 |
| IntelliJ IDEA | Community 即可（可选） | 打开后端工程用它内置 Maven，免装 Maven |
| Maven | 3.8+（可选） | 不用 IDEA 才需要自己装 |

## 2. 拉代码

两个独立仓库，建议放在同一个父目录下（前端代理、文档路径都按这个结构写）：

```bash
mkdir MusicDreamer && cd MusicDreamer
git clone https://codehub.devcloud.cn-north-4.huaweicloud.com/0bc98a43d532467eab9c79e071e6dc73/MusicDreamer-backend.git backend
git clone https://codehub.devcloud.cn-north-4.huaweicloud.com/0bc98a43d532467eab9c79e071e6dc73/MusicDreamer-frontend.git frontend
```

> 华为云 CodeHub 需要 HTTPS 寿命密码或 SSH Key 认证，没有的话在 CodeHub「个人设置 → HTTPS 密码」生成。

最终结构：

```
MusicDreamer/
├── backend/     # 后端仓库（微服务 + 基础设施编排 + 工具脚本）
└── frontend/    # 前端仓库（Vue3 + Vite）
```

## 3. 基础设施（MySQL + Redis + Nacos）

### 路线 A：Docker（推荐）

```bash
cd backend
docker compose up -d mysql redis nacos
```

**怎么算成功**（两条都满足）：

```bash
docker compose ps          # 三个容器都是 running / healthy
```

浏览器打开 <http://localhost:8848/nacos>（账号密码 nacos / nacos）能进控制台。

首次启动 MySQL 会自动执行 `init/init.sql` 建库建表，并写入默认管理员
`admin / admin123`。**只有第一次起（数据卷为空时）才会自动执行**；如果
`init/` 有更新且想重放，手动导入：

```bash
docker exec -i $(docker compose ps -q mysql) mysql -uroot -p123456 music < init/init.sql
```

#### Nacos 起不来？按顺序排查

1. **Docker Desktop 没在运行**：`docker version` 报错就先启动 Docker Desktop（等鲸鱼图标稳定）。
2. **镜像拉不下来**（国内网络常见）：`docker compose logs nacos` 里是拉取超时 → Docker Desktop 的 Settings → Docker Engine 里加国内镜像加速：
   ```json
   "registry-mirrors": ["https://docker.m.daocloud.io", "https://dockerproxy.com"]
   ```
   保存重启 Docker，再 `docker compose up -d nacos`。
3. **端口被占**：`netstat -ano | findstr "8848 9848 3306 6379"`，有输出就找到对应 PID 结束掉，或停掉本机已装的 MySQL/Redis/Nacos。
4. **一直 restarting**：`docker compose logs -f nacos` 看报错。最常见的坑：**Nacos 2.x 客户端走 9848 gRPC 端口**，只通 8848 是注册不上的——compose 里已经映射了 9848，别自己改掉。
5. 排查不动就整个重来：`docker compose down -v`（**会删数据**）再 up。

### 路线 B：不用 Docker

- **MySQL 8**：自己安装，root 密码直接设成 `123456`（和后端默认值一致，最省事），建库 `music` 并导入：
  ```bash
  mysql -uroot -p123456 -e "CREATE DATABASE IF NOT EXISTS music DEFAULT CHARACTER SET utf8mb4"
  mysql -uroot -p123456 music < backend/init/init.sql
  ```
- **Redis 6+**：Windows 用 [tporadowski/redis](https://github.com/tporadowski/redis/releases) 或 WSL 里装，默认端口 6379 无密码即可。
- **Nacos 2.2.3**：一条命令拉到 `tools/nacos`（Git Bash 里执行）：
  ```bash
  cd backend
  node scripts/fetch-tools.js --nacos
  ```
  然后双击 `scripts/nacos-start.cmd`（需要 JAVA_HOME 指向 JDK 17+）。
  验证同样是浏览器进 <http://localhost:8848/nacos>。

## 4. 媒体处理工具（下载/转码/歌词要用）

> 不做下载、转写歌词功能的话可以跳过，其余功能不受影响。

```bash
cd backend
node scripts/fetch-tools.js              # yt-dlp / ffmpeg / whisper-cli → tools/bin/
node scripts/fetch-tools.js --models     # 可选：whisper small 模型（约466MB，AI 歌词转写用）
```

- **必须在 Git Bash 里跑**（解压用到自带的 `unzip`），cmd/PowerShell 会失败。
- 下载源自 GitHub 时会自动切国内代理镜像；全部失败就重跑一次。
- 已存在的文件自动跳过，重复执行无副作用。
- 也可以先不跑，等系统起来后在 **管理端 → 工具管理** 页面点安装（同一套逻辑）。

## 5. 后端：编译与启动

### 编译

方式一（推荐）：IDEA 打开 `backend/` 工程，用它内置 Maven 直接跑启动类。

方式二：命令行（需要自装 Maven，JDK 用 17~22）：

```bash
cd backend
mvn -DskipTests package
```

### 数据库密码对齐（重要）

- 各服务默认连的是开发机的本机库（yml 里带默认值，包括密码）。
- 路线 A（Docker 的 MySQL）：root 密码是 `123456`，与 yml 默认值不同——**启动服务前设
  `MYSQL_PASSWORD=123456`**（Windows：`set MYSQL_PASSWORD=123456` / PowerShell：`$env:MYSQL_PASSWORD="123456"`，或写进 IDEA 运行配置的环境变量）。
- 路线 B（本机 MySQL）：root 密码设成 `123456` 最省事（起服务时同样设上面的环境变量即可）；用其他密码的照同样方式设 `MYSQL_PASSWORD=你的密码`。

### 启动

基础设施（MySQL/Redis/Nacos）健康之后，先起网关再起各模块。命令行方式：

```bash
java -jar gateway/target/gateway-1.0.0.jar
java -jar Mod_login/target/mod-login-1.0.0.jar
java -jar Mod_music/target/mod-music-1.0.0.jar
java -jar Mod_setting/target/mod-setting-1.0.0.jar
java -jar Mod_songList/target/mod-songList-1.0.0.jar
java -jar Mod_like/target/mod-like-1.0.0.jar
java -jar Mod_upload/target/mod-upload-1.0.0.jar
java -jar Mod_media/target/mod-media-1.0.0.jar
```

（IDEA 里就是依次跑各模块的 `*Application` 启动类。只调某块功能时，最小集是
gateway + Mod_login + Mod_music + Mod_setting。）

**怎么算成功**：打开 Nacos 控制台 → 服务管理 → 服务列表，能看到
gateway、mod-login、mod-music… 逐个上线；每个服务控制台无连不上 Nacos/MySQL 的报错。

## 6. 前端

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173，/api、/data 自动代理到本地网关 8080
```

## 7. 登录验证

- 默认管理员：**admin / admin123**（init.sql 写入，仅此一个种子账号）。
- 其他账号走注册：注册后系统发激活邮件——**没配邮箱服务时，激活链接直接打印在
  Mod_login 的控制台日志里**（搜 `[MAIL-未配置]`），复制链接到浏览器打开即激活。

全链路通了：登录 → 首页能出歌（目前是空库，先去上传/导入）→ 管理员审核 → 播放。

## 8. 常见问题速查表

| 症状 | 原因 / 解决 |
|---|---|
| 服务起不来，日志刷 Nacos 连接失败 | Nacos 没起或 9848 没通（见 §3 排查）；本机自装 Nacos 必须是 **2.2.x**，1.x 连不上 |
| 服务起不来，数据库拒绝连接 | 密码不对：Docker 的 MySQL 是 `123456`（起服务前设 `MYSQL_PASSWORD=123456`）；本机库密码与 yml 默认不同的，设 `MYSQL_PASSWORD=你的密码`（见 §5） |
| MySQL 容器 healthy 但没表 | 数据卷已存在时 `init.sql` 不会重跑，手动导入（见 §3 路线 A） |
| `fetch-tools.js` 报 unzip 不存在 | 在 Git Bash 里跑，不要用 cmd/PowerShell |
| 下载任务失败：yt-dlp 不存在 | `node scripts/fetch-tools.js` 拉工具；或管理端-工具管理页安装 |
| AI 歌词转写报模型未下载 | `node scripts/fetch-tools.js --models`，或管理端-模型管理页下载 |
| B 站下载 412 | 保持 yt-dlp 最新；反复出现就配 `download_proxy`（管理端-系统设置） |
| 前端接口全 404 / 跨域 | 网关没起；确认 8080 在跑，前端代理是 vite 自带的，别另起 nginx |
| 中文乱码 | JVM 参数加 `-Dfile.encoding=UTF-8`（IDEA：Help → Edit Custom VM Options） |
| 3306/6379/8848 被占 | 本机装过 MySQL/Redis/Nacos 且在跑：停掉或改端口，别和 Docker 的并存 |
