# MusicDreamer 2G 内存服务器部署手册

适用场景：2G 内存云服务器（课设演示），客户端为**微信小程序**，只跑基本业务（登录/听歌/搜索/歌单/收藏/歌词）。
不部署：Vue Web 前端（服务器上没有 nginx 托管它）、AI 听写（Whisper）、B站导入（Mod_media）、监控四件套。

## 架构一览

| 容器 | 作用 | 内存上限 |
|---|---|---|
| mysql | 业务库（init/init.sql 自动建 21 张表） | 450m |
| redis | token/缓存（全部使用方都有降级，挂了不丢功能） | 96m |
| nacos | 注册中心（standalone + Derby，堆压到 256m） | 400m |
| gateway | 唯一公网入口 :8080（JWT 校验 + 路由 + /data 转发） | 384m |
| mod-login | 登录/注册/微信小程序登录 | 320m |
| mod-music | 歌曲/搜索/榜单/播放统计 | 384m |
| mod-songlist | 歌单/专辑 | 320m |
| mod-like | 收藏 | 320m |
| mod-upload | 上传 + 音频流（/data/** 静态资源） | 320m |

合计上限 ≈ 2.9G（限制值，实际占用约 1.6-1.9G），必须配合 swap 才能在 2G 机器上稳定跑。

## 第 0 步：本机打包

```bash
bash scripts/pack-deploy.sh        # 产出 musicdreamer-deploy-*.tar.gz，约 341M（含 6 个核心 jar）
```

包内已含服务器构建镜像所需的全部：源码、`docker-compose.prod.yml`、`Dockerfile.service`、
6 个服务 jar（`*/target/*.jar`，Docker build 时 COPY）、`init/init.sql`、`data/`（音乐/封面/歌词）。
已排除：tools/、.git、node_modules、dist、Whisper 模型、data/task、docker-extras。

## 第 1 步：服务器准备（swap 必做）

```bash
# 上传解包
scp musicdreamer-deploy-*.tar.gz user@server:~/
ssh user@server
tar xzf musicdreamer-deploy-*.tar.gz && cd MusicDreamer-backend

# 加 2G swap（防启动高峰 OOM，必做）
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Docker（已装可跳过）
curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER
# 重连 shell 使 docker 组生效
```

## 第 2 步：配置微信密钥（可选）

```bash
cat > .env <<'EOF'
WX_APPID=你的小程序appid
WX_APP_SECRET=你的appsecret
EOF
chmod 600 .env
```

不配则微信登录接口返回参数缺失错误，其余功能不受影响（本地密码登录正常）。

## 第 3 步：构建并启动

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

首次构建：拉基础镜像 + COPY jar，约 5-10 分钟。启动顺序由 healthcheck + depends_on 自动编排：
mysql → redis → nacos → 6 个微服务。

```bash
# 验证
docker compose -f docker-compose.prod.yml ps          # 9 个容器应全为 Up/healthy
free -h                                               # 看内存水位
curl http://127.0.0.1:8080/api/v1/song/top            # 网关连通性
```

## 第 4 步：小程序接入

- 小程序请求 baseURL 改为 `http://<服务器IP>:8080`
- 演示阶段：微信开发者工具勾选「不校验合法域名」即可直连 HTTP
- 正式发布：需备案域名 + HTTPS（给网关前面加一层 nginx + certbot，或用云厂商负载均衡终结 TLS），
  并在微信公众平台配置 request 合法域名

> 安全提醒：prod 编排只暴露 8080。MySQL/Redis/Nacos 均无公网映射，密码是开发默认值
> （root/123456），正式对外前务必改掉，并在云安全组里只放行 8080（和 22）。

## 常见问题

| 现象 | 处理 |
|---|---|
| 某容器反复重启 | `docker logs <容器名>` 看堆溢出/OOM；`free -h` 确认 swap 已启用 |
| 启动高峰卡死 | 9 个 Java 容器不是同时就绪的，等 3-5 分钟；仍不行可分批 `up -d mysql redis nacos` 再 `up -d` |
| 服务报 Nacos 注册失败 | `docker logs nacos`；确认 nacos 容器 healthy |
| 歌曲播放 404 | `ls data/music/` 确认文件在；`sys_setting` 表 `storage_root` 应为空（走容器内 /data） |
| 想临时看 Nacos 控制台 | 给 nacos 服务临时加 `"8848:8848"` 端口映射后 `up -d nacos`，看完删掉 |

## 恢复/重建

```bash
# 改了配置重启
docker compose -f docker-compose.prod.yml up -d

# 完全重来（保留数据库）
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d --build

# 清库重来（危险：init.sql 只在 mysql_data 卷为空时执行）
docker compose -f docker-compose.prod.yml down -v
```
